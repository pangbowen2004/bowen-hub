# 04 论文阅读馆（Paper Library）

## 1. 目标

把读过的论文变成一座自己的中文论文馆：每篇论文有一篇能独立读懂的中文导读，导读里的每个事实都能点开看到原文摘录和页码；论文之间通过概念和研究空间连成图谱。新论文上传后自动出导读草稿，Kevin 读过、点“公开”就上线。

| 形态 | 地址 | 内容 | 用途 |
|---|---|---|---|
| **公开站** | https://bowen-paper-library.pages.dev/ （保持不变） | 只有 `visibility = public` 的论文；只读；静态页面 | 对外展示（已写进求职材料） |
| **控制台** | `https://bowen-console.pages.dev/papers` | 全部论文 + 私人内容（笔记、掌握状态、解释卡、老阅读卡）+ 原文页 + 整篇原文问答 + 上传与审核 + 公开开关 | Kevin 自己读、管理；手机也能用 |
| **MCP** | `https://bowen-console.pages.dev/mcp` | `papers_search` `papers_get` `papers_ask` `papers_ingest_url` | 在 Claude、ChatGPT 里查论文、问论文、提交论文 |

现状：89 篇档案，公开 19 篇，69 篇读完但卡在发布流程。新系统里，公开就是一个按钮。

## 2. 内容模型

### 2.1 存在哪里

| 内容 | 契约模型 | 存储 |
|---|---|---|
| 一篇论文的全部公开内容 | `Paper` | D1 `papers.doc`（另有 `summary` 和几个状态列，`09` 第 3 节） |
| 列表和卡片用的摘要 | `PaperSummary` | D1 `papers.summary`，由写入方（计算任务）算好一起写入 |
| 私人内容 | `PaperPrivate` | D1 `paper_private` |
| 审核记录 | `Review` | D1 `paper_reviews`（每次审核一条） |
| 原文 PDF、页文本、页图 | — | R2 `papers/<id>/…`（`09` 第 4 节） |
| 目录、图谱、搜索索引（派生） | `PapersCatalog` `GraphData` `SearchIndex` | D1 `documents`（第 6 节） |

`id` 规则沿用老系统：`arxiv-2505.07078`、`acl-2025.acl-long.773`、`doi-10.1016-j.jfineco.2011.11.003`、`ssrn-4115411`；没有公开编号的用 `custom-<短名>`；同一论文不同版本加后缀 `-v1` / `-v2`。

```jsonc
    "secondary": [{ "title": "QuantML 导读……", "note": "二手材料，不等同原文" }]
  },
  "citations": { "backward": [{ "title": "…", "why": "…" }], "forward": [] },
  "relations": [{ "target": "arxiv-2409.06289-v1", "type": "version_of", "note": "…" }]   // 只放明确声明的论文间关系
}
```

规则：
- `schemaVersion`、`id` 与 API 路径一致；`status.visibility` 和 `spaces` 也存在表的列里，控制台修改时两处一起改（`09` 第 1 节）。
- 除 `id`、`meta.title`、`status` 外，其余字段都允许缺省；页面遇到缺省的部分就不显示那一块。
- `guide.article` 里的段落与 `evidence.articleBlocks` 一一对应：把正文按空行切段，**纯标题行不算段**，第 i 段对应 `articleBlocks[i]`。
- 论文事实的出处一律用 `claims`；导读正文里不出现 `c1` 这类内部编号，出处写成自然的“论文 p.7, Table 1”。


### 2.3 导读正文的 8 个固定二级标题

先说结论 / 论文为什么要做这件事 / 核心方法到底怎么运转 / 实验怎样检验这个方法 / 结果说明了什么 / 这篇论文哪里最强，哪里最危险 / 代码从哪里读 / 读完后记住这三件事

（理论论文在“实验”一节写命题与证明、反例；综述写纳入标准与比较。不为了凑模板编造实验。）

## 3. 公开站页面

构建时从公开 API 读取数据（`/v1/public/papers/catalog`、`/papers/{id}`、`/papers/graph`、`/papers/search-index`；本地和 CI 可用 `DATA_SOURCE=fixtures`）；**首屏 HTML 里就有内容**，浏览时不调用任何 API。

| 路径 | 内容 |
|---|---|
| `/` 论文馆首页 | 标题“论文阅读馆”；统计（论文数、研究空间数、概念数）；搜索框；筛选（研究空间、年份、论文类型、阅读深度）；排序（最近更新 / 年份）；论文卡片（中文标题、英文标题、venue·年份、一句话结论、研究空间标签、阅读深度） |
| `/papers/[id]/` 单篇 | 见下表 |
| `/graph/` 论文图谱（2D） | 两种视图切换：**论文—概念关系图**（节点：论文、概念、研究空间；边：论文讨论概念、论文属于空间、明确声明的论文间关系）；**概念共现图**（两个概念出现在同一篇论文里就连线，线越粗共现越多）。点击论文节点进入单篇页；搜索高亮节点；图例 |
| `/universe/` 3D 知识宇宙 | 论文和概念放进可旋转的三维空间，点击进入单篇页。只在这个页面懒加载 3D 库；手机上提示“在电脑上体验更好”并给 2D 图谱入口 |
| `/spaces/[space]/` 研究空间 | 空间说明 + 该空间的论文列表 |
| `/about/` 关于 | 这个论文馆怎么读论文（R0–R3、证据规则）、更新时间 |

**单篇页 `/papers/[id]/` 的结构**（从上到下）：
1. **标题区**：中文标题（大）、英文原题、作者、venue·年份、版本；论文类型、研究设计；徽标：阅读深度、研究空间、代码状态；链接：原文主页、代码。
2. **30 秒速览**：一句话结论、阅读目标；“能支持 / 不能支持 / 一句话记住”（`bottomLine`）。
3. **读前须知**：术语卡片（`prerequisites`）。
4. **导读正文**：渲染 `article`。每个有证据的段落旁边有一个小的证据标记，点开浮层显示对应 claims：主张、指标、条件、原文摘录、页码、解读边界。`claimOrigin = llm_inferred` 的段落显示“解释性推断”标签。
5. **关键证据**：claims 表（类型、主张、指标、条件、锚点、边界），可按类型筛选。
6. **读完自测**：`readerCheck` 七问和 `activeRecall`，答案默认折叠。
7. **技术附录**（默认折叠）：问题 → 方法 → 实验 → 发现的结构卡（`problem` `method` `experiment` `findings`）；学习卡（是什么、类比、为什么重要、容易混淆的、机制步骤、设计思路、专家问答）；图表说明、概念、文档地图、局限、待核查问题。
8. **批判预审**（默认折叠）：最小结论、最容易被夸大的说法、各维度判断、负结果与小效应；阅读完成度（按 `coverage` 计算：完整 = 1、部分 = 0.5、缺失 = 0，不适用的不计；页面注明“这是阅读覆盖度，不是论文质量分”）。
9. **延伸阅读**：引文导航（向后 / 向前）、代码入口、二手材料说明、相关论文（同概念的最多 5 篇、同空间、明确声明的关系；同概念的只在页面列出，图谱里不连边）。

另外发布两类给 AI 读的文件（`05` 第 1 节）：
- `/papers/[id].md`：单篇的 Markdown 版（导读正文 + 关键证据表，保留页码锚点）。
- `/llms.txt`：站点说明 + 所有公开论文的标题、一句话和 `.md` 地址。

## 4. 控制台里的论文功能

页面（`05` 第 4 节）：`/papers` 全部论文 · `/papers/$id` 阅读 · `/papers/inbox` 入库与待审 · `/papers/graph` 全部论文的图谱。

`/papers/$id` 的正文部分和公开站单篇页相同（同一套组件），另外增加：

| 功能 | 说明 | 接口（`08` 第 5.1 节） |
|---|---|---|
| 全部论文 | 包括私有和草稿，卡片上显示“未公开”“草稿”“需修改” | `GET /v1/papers` |
| 公开开关 | “公开 / 取消公开”按钮；列表页可多选批量公开；改完后公开站几分钟内自动更新（`12` 第 3 节） | `PATCH /v1/papers/{id}` |
| 阅读深度、下一步、研究空间 | 直接改 | `PATCH /v1/papers/{id}` |
| 掌握状态、笔记 | 待确认 / 已确认；笔记自动保存 | `PUT /v1/papers/{id}/private` |
| 问这篇论文 | 侧边抽屉提问，流式回答，回答里标页码；满意的点“保存为解释卡”（状态 pending，可改 confirmed） | `POST /v1/papers/{id}/ask`、`/explanations` |
| 原文页 | 点证据浮层或回答里的页码，显示该页原图 | `GET /v1/papers/{id}/pages/{n}` |
| 老阅读卡 | 显示迁移来的 R0、R1、QuantML 导读原文 | 随 `PaperPrivate` 返回 |
| 审核记录 | 最近一次审核的结论、发现的问题（按 P0/P1/P2）、抽查过的页 | `GET /v1/papers/{id}/reviews` |
| 按意见重写 | 写几句修改意见（比如“第三节的例子换成……”），系统带着意见重写草稿（第 5.4 节） | `POST /v1/papers/{id}/revise` |
| 导出 Markdown | 导读正文 + 关键证据（保留页码锚点）导出成 `.md`，在浏览器里生成 | — |

**问答怎么做**（能力 `papers.qa`，在 API 里运行，`10` 第 3 节）：
- 上下文 = 这篇论文的 `guide` + `evidence.claims` + **整篇原文**（R2 里的 `pages.txt`，每页以 `=== p.N ===` 开头）。论文通常 1–4 万 token，GPT-6 系列的上下文约 105 万 token，不需要检索。
- 原文超过 `papers.qa` 清单里的 `limits.maxInputTokens` 时（极少数超长论文；Worker 里不跑分词器，token 数按字符数 ÷ 3 估算），按顺序放入：被 `claims` 引用的页 → 前 10 页 → 其余页，直到上限。
- 只根据材料回答，页码必须在范围内（校验 `pages_in_range`）；每次问答记进 `ai_calls`，按起步配置一次不到 1 美分。
- MCP 的 `papers_ask` 走同一个能力。

## 5. 入库流水线

### 5.1 流程

```text
控制台上传 PDF（或贴 arXiv 链接；MCP 的 papers_ingest_url 同理）
  → API：PDF 存进 R2 uploads/，记一条 paper_uploads（queued），触发 papers-ingest 工作流
papers-ingest（GitHub Actions）：hub papers ingest <uploadId>
  （本机也可以直接跑：hub papers ingest --file <PDF> 或 --arxiv <链接>，流程相同）
  1. extracting  取得 PDF；用 PyMuPDF 抽每页文本并编行号 → pages.jsonl 和 pages.txt（格式见本节末）；生成每页的 PNG 页图
                 （第 1–5 步的文件都放在运行环境的本地目录里，第 6 步才写进 R2）
  2.             定 id：前两页文本里找 arXiv 编号 / ACL Anthology 编号 / DOI / SSRN 编号，有多个时按这个顺序取
                 （DOI 转小写，“/”换成“-”）；都没有就等第 3 步写出英文标题后用 custom-<短名>
                 （标题前 6 个实词，去掉 a、an、the、of、for、and、in、on、with、to、via、from、by 等常见虚词，
                 小写、用短横线连接，最长 40 个字符）；
                 id 已存在时：编号和版本都相同 → 视为重复，上传记录报“已存在”，不入库；
                 编号相同、版本不同 → 加 -v2、-v3，并在 relations 里写 version_of；
                 定下的 id 立刻写进上传记录（PATCH /v1/internal/papers/uploads/{uploadId}，Upload 的 paperId），
                 重试时沿用这个 id、覆盖写入，不再加 -v2
  3. authoring   能力 papers.author（frontier）读整篇原文，按 prompts/paper_author.md 写草稿（id 未定时 paperId 传“待定”）
  4. checking    确定性校验（第 5.2 节）；不通过 → 带着错误清单让 papers.author 修改，最多 2 轮
                 （轮数在 capabilities/papers.author.yaml 的 params.repairRounds）
                 通过后，按 claims 的 pdfPage + sourceLines 从页文本里取出原文，填进 sourceExcerpt
  5. reviewing   能力 papers.review（frontier）按 prompts/paper_review.md 审核：整篇原文 + 草稿，
                 另附证据里引用到表格或图的页的页图：anchor 匹配 Table|Tab.|Figure|Fig.|表|图 的 claims 的 pdfPage，
                 去重后按在 claims 里出现的先后取前 8 页（模型不支持图片时只给文本）
                 结论 revise 且有 P0 或 P1 问题 → 带着审核意见让 papers.author 再改 1 轮（params.reviewRounds），重新校验和审核
  6. 写入 API：PDF、pages.jsonl、pages.txt → PUT /v1/internal/papers/{id}/files/{name}；
     页图 → PUT /v1/internal/papers/{id}/pages/{n}；
     PUT /v1/internal/papers/{id}（visibility = private，review = passed / revise / draft；
       spaces = ["general-research"]，status.readingDepth = R0，status.nextAction = “通读导读草稿，确认后公开”，
       这三项 Kevin 在控制台改）；
     POST /v1/internal/papers/{id}/reviews；上传记录改为 ready
  7. hub papers derive（第 6 节），控制台的目录和图谱里出现这篇
任何一步失败：上传记录改为 failed 并写明原因；控制台“入库”页显示，可以一键重试（POST /v1/papers/uploads/{uploadId}/retry）
```

- 审核结论到状态：`pass` → `passed`；`revise` → `revise`；`escalate` → `revise`，控制台标“需要你判断”。审核能力本身失败 → `draft`（没审过）。
- 新论文一律先是私有的。**公开只由 Kevin 在控制台点按钮**（L1，`10` 第 6 节）。
- 一篇论文的入库大约 5–15 分钟；按起步配置（frontier = `gpt-6-sol`），含修订轮次每篇的 AI 费用约 0.5–1.5 美元。
- 新论文只有 `papers.author` 写出的内容：学习卡（`learning`，含读完自测的 `activeRecall`）、技术附录里的结构卡（`problem` `method` `experiment` `findings`）和批判预审（`appraisal` `coverage` `negativeResults`）都不生成，页面遇到缺省的块就不显示。
- 页文本格式：`pages.jsonl` 每行是一页 `{"page": n, "lines": ["…"]}`，`lines` 里去掉空行，行号 = 下标 + 1（每页从 1 起）；`pages.txt` 每页以 `=== p.N ===` 开头。给 `papers.author`、`papers.review` 和 `TASK.md` 的带行号页文本：每页以 `=== p.N ===` 开头，之后每行写成 `L{行号}: 内容`。

### 5.2 确定性校验（`hub papers check`，能力清单里的 `paper_draft` 校验）

只查格式和可核对的事实，不做“门禁”：

| 检查 | 规则 |
|---|---|
| 结构 | 符合契约（生成的 Pydantic 模型）；必填字段非空 |
| 导读标题 | `article` 恰好有 2.3 节的 8 个二级标题，顺序一致 |
| 段落对应 | `articleBlocks` 数量 = 正文段落数（纯标题行不算段） |
| 引用覆盖 | `claimOrigin = paper_supported` 的段落，`claimIds` 至少 1 个且都存在；`llm_inferred` 的段落正文里要出现“解释性例子”“核查建议”或“我的推断”之一 |
| 页码与行号 | `1 ≤ pdfPage ≤ 页数`；`sourceLines` 在该页行数范围内 |
| 数字对得上 | 每个 `quantities[].sourceText` 都出现在对应的原文行里；`metric` 里出现的每个数字都在 `quantities` 里 |
| 读者自测 | `readerCheck` 七项都有内容 |
| 代码链接 | `resources.code.status = verified` 时必须有 `url` |

不做：版本绑定、审核回执、冻结快照、发布基线、哈希比对。要追溯看数据仓库 `bowen-hub-data` 的历史。

### 5.3 让本机的 Agent 代写（可选）

Kevin 想用自己电脑上的 Agent（Claude Code、Codex、Gemini CLI 等）写某一篇时：

```bash
hub papers task --file <PDF>      # 抽页文本，在 .work/<id>/ 生成 TASK.md（作者提示词 + 元数据 + 带行号的页文本）
（Agent 按 TASK.md 写 .work/<id>/draft.json）
hub papers check .work/<id>/draft.json   # 本地校验，按中文错误清单修改
hub papers submit --file <PDF> .work/<id>/draft.json   # 用这份草稿代替第 3 步，其余照第 5.1 节走完（校验、审核、写入）
```

对已经入库的论文，`hub papers task <id>` 从 API 取页文本，`hub papers submit <id> <草稿>` 用新草稿替换。

`.work/` 不入库。

### 5.4 按意见重写

控制台“按意见重写” → API 触发 `papers-revise` → `hub papers revise <id> --instructions "<意见>"`：把现有草稿、Kevin 的意见和整篇原文交给 `papers.author`，然后照常校验、审核、写回。写回时只替换草稿（`PaperDraft`）覆盖的字段，其余字段原样保留；`evidence` 整块换成新的（新行号，`legacyAnchors = false`）。迁移来的老论文重写后，导读的二级标题会规范成 2.3 节的 8 个。重写不会改变公开状态；已公开的论文重写后仍是公开的，公开站在下一次部署时更新。

### 5.5 公开

控制台点“公开” → `PATCH /v1/papers/{id}`（`visibility = public`）→ API 发出 `papers-changed` → `deploy-papers.yml`：`hub papers derive` → 从 API 构建公开站 → 发布（`SITES_LIVE = true` 时发到正式网址，`12` 第 2 节）。取消公开同理。

## 6. 派生数据（`hub papers derive`）

读全部论文，生成两份（`public` 只含公开论文；`all` 含全部），写进 `documents`：

| key | 内容 |
|---|---|
| `papers.catalog.public` / `papers.catalog.all` | 统计（论文数、研究空间数、概念数、边数）、研究空间（来自 `config/paper_spaces.yaml`，含每个空间的论文数）、全部 `PaperSummary` |
| `papers.graph.public` / `papers.graph.all` | 图谱。节点：论文、概念、研究空间；边：`discusses`（论文 → 概念）、`belongs_to`（论文 → 空间）、`relation`（`relations` 里明确声明的论文间关系）；另给 `cooccurrence`（概念对 → 共现次数） |
| `papers.search.public` | 公开站本地搜索的数据（标题、作者、一句话、概念名、空间名） |

- 概念归并：名称统一小写、去空格后相同的视为同一概念；`config/paper_concept_aliases.yaml` 里可以手工合并同义词。
- **不再自动生成“共享核心概念”这类论文—论文相似边**（老系统按标题里的 “series”“time” 这类词连了 1,128 条边，基本是噪声）。单篇页仍可列出同概念的论文（最多 5 篇，第 3 节），但图谱里不连边。
- **“哪些内容能公开”只在这一个地方决定**：`public` 版本只从 `visibility = public` 的论文生成，不含任何 `PaperPrivate` 内容；公开 API 的 `/papers/{id}` 对私有论文返回 404。

## 7. 研究空间

`config/paper_spaces.yaml` 定义：`id`、`label`、`shortLabel`、`color`、`description`、`aliases`。首批 3 个：
- `agent-systems` Harness 与智能体（合并老系统里重复出现的自定义空间）
- `quant-finance` 量化金融
- `general-research` 通用研究（未归入特定领域的论文）

一篇论文可以属于多个空间。新增空间：改这个配置，然后 `hub papers derive`。
