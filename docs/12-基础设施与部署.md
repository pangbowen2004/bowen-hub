## 3. 工作流一览（`.github/workflows/`）

| 工作流 | 触发 | 做什么 |
|---|---|---|
| `ci.yml` | PR、push 到 main | `11` 第 8 节 |
| `deploy-api.yml` | push 到 main（改到 `services/api`、`packages/contracts`、`packages/ai`、`capabilities`、`prompts`、`config/llm.yaml`）；手动 | `wrangler d1 migrations apply --remote` → `wrangler deploy` |
| `deploy-console.yml` | push 到 main（改到 `apps/console`、`packages/ui`、`packages/contracts`）；手动 | 两次构建：正式版 → 生产；MSW 模拟版（`VITE_USE_MOCKS=1`）→ `preview` 分支 |
| `deploy-markets.yml` | `repository_dispatch: markets-updated`（由 `market-eod` 发出）；push 到 main（改到 `apps/markets`、`packages/ui`）；手动（输入：`data_source` = api / fixtures，`target` = preview / production） | 构建 → 发布（数据触发时用 `api`，`SITES_LIVE` 决定生产还是预览；API 里还没有数据时用 `fixtures` 发预览） |
| `deploy-papers.yml` | `repository_dispatch: papers-changed`（Kevin 在控制台改了论文的公开状态或研究空间时，由 API 发出）；push 到 main（改到 `apps/papers`、`packages/ui`）；手动（输入同上） | `hub papers derive`（`data_source = api` 时）→ 构建 → 发布 |
| `news-morning.yml` 等定时任务 | cron | 见 `09` 第 8 节 |
| `papers-ingest.yml` | `repository_dispatch: papers-ingest`、`papers-revise` | `hub papers ingest` / `hub papers revise` |

- 所有工作流设 `concurrency`：同一个任务不重叠；部署类用 `cancel-in-progress: true`，连续点了 5 次“公开”只会构建最后一次。
- GitHub 免费版的私有仓库**不能**给环境设置“必须审批”（这个功能只对公开仓库开放），所以“生产发布需要确认”靠第 2 节的 `SITES_LIVE` 变量和手动触发实现。
- Python 依赖用 `astral-sh/setup-uv` 的缓存；TuShare 的原始数据用 `actions/cache` 缓存（键：接口 + 交易日），补跑历史时不重复拉取。

- 密钥只从环境变量读；不打印、不写日志、不提交。`.env` 不入库。

- 仓库变量（不是密钥）：`SITES_LIVE`。
- Worker 的普通变量（写在 `wrangler.jsonc` 的 `vars` 里，不是密钥）：`GITHUB_REPO`（`<GitHub 用户名>/bowen-hub`，发 `repository_dispatch` 用）、`AUTH_BASE_URL`（`https://bowen-console.pages.dev`）、`AUTH_RP_ID`（`bowen-console.pages.dev`）、`AUTH_TRUSTED_ORIGINS`（`https://bowen-console.pages.dev`；本地开发另配 `http://localhost:5173`）、`CLOUDFLARE_ACCOUNT_ID`、`AI_GATEWAY_ID`。

## 5. 每月用量估算（免费额度内）

| 资源 | 估算 | 免费额度 |
|---|---|---|
| GitHub Actions 分钟 | 约 1,200 分钟（下表） | GitHub Free 私有仓库一般 2,000 分钟（以账单页为准） |
| Workers 请求 | 每天几百到几千次（控制台、构建、计算任务、MCP） | 每天 10 万次 |
| D1 存储 | 起步约 50 MB；新闻条目每天约 0.5 MB，保留 365 天后稳定在约 200 MB 以内（论文约 90 篇 × 每篇约 0.3 MB、市场每天约 0.15 MB） | 单库 500 MB |
| R2 存储 | 约 1 GB（论文 PDF 约 690 MB + 页图约 400 MB + 邮件存档） | 10 GB |
| AI 费用 | 起步配置下：新闻约 3–5 美元 / 月（大头是 frontier 档的导语）；每篇新论文导读约 0.5–1.5 美元（含修订轮次）；问答每次不到 1 美分；每周评测约 1 美元 / 月（论文作者和审核的评测只在改动时跑）。每月合计预计 10–20 美元，月度预算设 20 美元 | 按量付费 |

GitHub Actions 分钟估算：

| 工作流 | 次数 × 每次 | 分钟 / 月 |
|---|---|---|
| 早报（两个触发点，后备那次 1 分钟内退出） | 30 × 4 + 30 × 1 | 150 |
| 盘前（两个触发点，不在时间窗口的那次 1 分钟内退出） | 22 × 4 + 22 × 1 | 110 |
| 周报 | 4 × 6 | 24 |
| A 股收盘（每小时触发，完成后后续几次 1 分钟内退出） | 22 × (6 + 5 × 1) | 242 |
| 部署市场站 | 22 × 3 | 66 |
| 论文入库 + 部署论文站 | 10 × 12 | 120 |
| 每周评测 | 4 × 8 | 32 |
| 每晚导出 | 30 × 2 | 60 |
| CI（开发期更多，稳定后） | 约 100 次 × 4 | 400 |
| **合计** | | **约 1,200** |

开发集中的月份，CI 可能超出估算。分钟不够时：CI 只在 PR 上跑，不在每次 push 上跑；端到端和 Lighthouse 只在相关目录有改动时跑。仓库含私人数据，不改成公开。

## 8. 升级路径（现在不做）

| 触发条件 | 升级 |
|---|---|
| Worker 里需要更长的 CPU（例如 L3 自主能力在 API 里多步推理） | Workers 付费版（$5/月），同时解锁更长的 Workflows 步骤 |
| 想要“上传即入库”全在云端完成、不经过 GitHub Actions | Cloudflare Workflows 编排；PDF 处理仍可交给 Actions |
| 数据超出 D1 的 500 MB | 换 Postgres（Neon 免费档），Drizzle 换方言，契约不变 |
| GitHub Actions 分钟长期不够 | 把定时任务搬到 Workers Cron + Workflows（需要付费版） |
