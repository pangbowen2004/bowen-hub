# 05 前端规范

三个前端应用共用一套设计系统 `packages/ui`。两个公开站会被招聘方打开，第一印象要专业、干净、快；控制台是 Kevin 每天在手机和电脑上用的工具，要顺手。

## 1. 原则

1. **内容先到。** 公开站的内容在构建时写进 HTML；JS 只负责交互（排序、筛选、图表、图谱、搜索）。关掉 JS 也能读到全部文字和表格。
2. **一眼看懂，点开有细节。** 先给结论和关键数字；公式、明细、边界说明默认折叠，需要时展开。
3. **同一套语言。** 三个应用用同样的字体、间距、组件和交互方式，只有主色不同。
4. **中文优先。** 界面文字全部中文；数字、代码、公式用等宽或表格数字。
5. **不装饰。** 不用大图、背景视频、花哨动画；图表只在能说明问题的地方出现。
6. **平台原生优先。** 折叠用 `<details>`，浮层用 `popover` 属性，对话框用 `<dialog>`，页面切换用 View Transitions；能不写 JS 就不写。
7. **只认契约。** 前端只通过 `packages/contracts` 生成的客户端和类型访问数据，不手写接口类型，不直接碰数据库和后端代码。唯一例外是流式问答（`POST /v1/papers/{id}/ask`），用 AI SDK UI 调用（`08` 第 5.1 节）。
8. **对 Agent 友好。** 公开站为主要内容同时发布 Markdown 版（论文单篇、市场每日摘要、周报），并提供 `/llms.txt`（站点说明 + Markdown 地址），方便 AI 读取和引用。

## 2. 三个应用

| 应用 | 技术 | 数据从哪来 | 本地端口 | 发布到 |
|---|---|---|---|---|
| `apps/markets` A 股观测台 | Astro 6 静态输出 + React 岛 | 构建时读公开 API（`DATA_SOURCE=api`）或 `fixtures/samples/`（`DATA_SOURCE=fixtures`） | 4321 | `bowen-market-observatory` |
| `apps/papers` 论文阅读馆 | 同上 | 同上 | 4322 | `bowen-paper-library` |
| `apps/console` 控制台 | React 19 + React Compiler + Vite + TanStack Router（文件路由）+ TanStack Query；流式问答用 AI SDK UI | 运行时经同源代理调用 API（`01` 第 5 节）；开发时默认 MSW 模拟（`VITE_USE_MOCKS=0` 切到本地 API） | 5173 | `bowen-console` |

`packages/ui` 的结构：

```text
packages/ui/src/
├── styles/      tokens.css（设计令牌）、base.css；Tailwind v4 用 @theme 引用令牌
├── astro/       静态组件（.astro），公开站用
├── react/       交互组件（React），控制台和公开站的 React 岛都用
├── charts/      ECharts 的 React 包装
└── format/      格式化函数（第 8 节），三个应用统一使用
```

每个组件都有 Storybook 故事；交互组件有组件测试。

## 3. 设计令牌（`packages/ui/src/styles/tokens.css`）

用 CSS 变量定义，Tailwind v4 通过 `@theme` 引用；同时提供浅色和深色（跟随系统 `prefers-color-scheme`，控制台另有手动切换）。

| 类别 | 规定 |
|---|---|
| 字体 | 界面：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", sans-serif`；等宽：`"SF Mono", "JetBrains Mono", Menlo, monospace`。**不下载网络字体**（中文字体文件太大） |
| 数字 | 表格、指标、价格一律 `font-variant-numeric: tabular-nums`，右对齐 |
| 字号 | 12 / 14 / 16（正文）/ 18 / 22 / 28 / 36 |
| 行高 | 界面 1.5；长文（论文导读、新闻正文）1.85，正文栏宽不超过 72 个汉字 |
| 间距 | 4px 基准：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 |
| 圆角 | 6（小元素）/ 10（卡片） |
| 中性色 | 背景、表面、边框、正文、次要文字、弱化文字，各给浅色和深色两套值 |
| 主色 | 市场站：墨蓝 `#2f5bd3`；论文站：青绿 `#0f766e`；控制台：靛蓝 `#4f46e5`（深色模式各自提亮） |
| 状态色 | 信息（蓝）、提醒（琥珀）、缺失/不可用（灰），**不用红绿表示状态** |
| 断点 | 640 / 768 / 1024 / 1280 |

## 4. 涨跌颜色

- **全站红涨绿跌**（A 股惯例，也是 Kevin 看美股的习惯；新闻邮件同样如此）。涨 `--up`（浅色 `#d93025`，深色 `#ff6b5f`），跌 `--down`（浅色 `#188038`，深色 `#4cc38a`），平 `--flat`（灰）。
- 涨跌不只靠颜色：数字带正负号，必要时加 ▲▼。
- 热力图用以 0 为中心的红—灰—绿发散色阶。
- 红和绿只用于涨跌；状态徽标、按钮、提示都不用红绿。

## 5. 布局

**公开站**
- 内容最大宽度 1200px（论文正文栏 720px）；左右留白手机 16px、桌面 32px。
- 顶部导航：站名 + 栏目；1024px 以下折叠成菜单按钮。
- 宽表格放在可横向滚动的容器里，首列固定；**页面本身在 390px 宽时不能出现横向滚动**。
- 每页顶部：页面标题 + 一句导语 + 数据日期（市场站还有“上一交易日 / 下一交易日”）。
- 页脚：数据来源、更新时间、免责声明（市场站）。

市场站各栏目导语（沿用老站文字）：
- 驾驶舱：由当日状态摘要标题代替。
- 行业与涨停：行业状态不是涨幅榜，而是一组等待验证的结构线索。
- 方向与 ETF：从成分宽度到 ETF 份额，同一交易日交叉验证。
- 演化与事件：不只看今天涨了什么，还要看结构如何迁移。
- 验证中心：到期问题，必须结算，或者明确说明证据缺口。
- 方法与口径：每一个数字，都要能回到定义和来源。

**控制台**
- 桌面：左侧导航栏 + 内容区；手机：底部标签栏（今日 · 新闻 · 论文 · 更多）。
- 列表页支持下拉刷新和无限滚动（游标分页）。
- 所有写操作乐观更新，失败时回滚并提示。

## 8. 格式化（`packages/ui/src/format/`，全站统一）

| 函数 | 规则 | 例子 |
|---|---|---|
| `pct(x, {sign, digits})` | 0–1 小数转百分比，默认 2 位 | `0.0123 → +1.23%` |
| `pp(x)` | 百分点差 | `0.031 → +3.1 个百分点` |
| `cny(x)` | ≥1e12 用“万亿”（4 位小数），≥1e8 用“亿”（≥100 亿 1 位小数，<100 亿 2 位小数），≥1e4 用“万” | `2117732336241 → 2.1177 万亿` |
| `usd(x)` | ≥1e9 用 `B`，≥1e6 用 `M`，否则千分位；带 `$` | `1250000 → $1.25M` |
| `count(n, unit)` | 整数 + 单位 | `83 家` |
| `date(d)` | `2026-08-28（周五）` | |
| `time(t, tz)` | 默认新加坡时间；美股日程同时显示美东时间 | `21:30（美东 09:30）` |
| `num(x, digits)` | 千分位 | `3,952.18` |

所有格式化都在前端做，接口和文档里只存原始数值。

## 9. 图表约定

- 统一用 ECharts，按需引入；主题色、字体、网格线从设计令牌读取。
- K 线：红涨绿跌（ECharts 默认即如此，保持）；叠加 MA5/10/20；支撑/压力画水平虚线并标注。
- 提示框中文，数值用第 8 节的格式化函数。
- 图表下面一行小字写数据来源和口径。
- 能用表格说清的，不画图。

## 10. 性能预算

| 页面类型 | 首屏 JS（gzip） |
|---|---|
| 公开站普通内容页（首页、单篇、列表、方法、周报） | ≤ 50 KB（多数为 0：证据浮层和折叠都是原生能力） |
| 公开站含交互表格的页面 | ≤ 120 KB |
| 公开站含图表的页面、2D 图谱 | ≤ 250 KB（图表库在滚动到可见时才加载） |
| 3D 宇宙 | 不限，但必须懒加载并有加载状态 |
| 控制台 | 首屏 ≤ 250 KB；按路由拆包 |

- 不用网络字体；图标用内联 SVG。
- 公开站每个页面有 `<title>`、`description`、Open Graph 标签（在 LinkedIn/微信分享时有标题和摘要）；站点有 favicon、sitemap、`llms.txt`。
- Lighthouse 移动端：性能 ≥ 90、可访问性 ≥ 90（图谱和 3D 页除外）。

## 11. 可访问性与适配

- 语义化 HTML（`header` `nav` `main` `section` `table` `th scope`）。
- 文字对比度达到 WCAG AA；所有可点元素有清楚的焦点样式。
- 支持深色模式；尊重 `prefers-reduced-motion`。
- 手机（390px）、平板（768px）、桌面（1440px）三档都要检查。

## 12. 端到端冒烟测试（Playwright）

对两个公开站的每个主要页面（用 `DATA_SOURCE=fixtures` 构建），在 1440px 和 390px 两种宽度下检查：
- 页面能打开，HTTP 200；浏览器控制台没有错误；
- `document.documentElement.scrollWidth <= window.innerWidth`（没有横向溢出）；
- 关键元素存在（例如驾驶舱的标题和关键数字条、论文首页的论文卡片）；
- 浏览期间没有任何对 API 的请求。

控制台（MSW 模拟数据）：登录页可见；各主要路由能打开；论文页的笔记保存、公开开关、问答抽屉（模拟流式回答）能走通；新闻一期的打分能提交。
