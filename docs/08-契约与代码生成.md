# 08 契约与代码生成

## 1. 为什么契约优先

- **并行**：契约先定下来，前端、后端、计算任务就能同时开工。前端用生成的模拟数据跑，后端照着生成的校验器实现，计算任务照着生成的 Pydantic 模型产出。
- **两种语言同一套类型**：TS 和 Python 的类型都从同一份定义生成，不会各写各的。
- **可检查**：接口改动是否破坏兼容，CI 自动判断。

## 2. 目录

```text
contracts/
├── tspconfig.yaml
├── main.tsp              # 入口：服务元信息、版本、安全方案，导入其余文件
├── common.tsp            # 通用：日期、分页、错误（RFC 9457）、出处（generatedBy）、比例/金额约定
├── news.tsp              # Article、Filing、InsiderTrade、CalendarEvent、TickerDigest、EarningsCard、Edition、Feedback
├── watchlist.tsp         # WatchItem
├── markets.tsp           # MarketDay 及其各块、MarketDaySummary、IndexBar、Hypothesis、WeeklyReport、MarketEvent、MarketReference
├── papers.tsp            # Paper、PaperPrivate、PaperSummary、PapersCatalog、GraphData、SearchIndex、Review、Upload
├── platform.tsp          # Run、AiCall、EvalResult、CapabilityInfo、Health、Document
├── capabilities.tsp      # 每个 AI 能力的输入/输出模型（capabilities/*.yaml 引用这里的名字）
├── routes/               # 接口定义：public.tsp、private.tsp、internal.tsp
└── generated/            # 生成物（入库，勿手改）
    ├── openapi.yaml      # OpenAPI 3.1
    └── schemas/*.json    # JSON Schema（数据文档与能力 I/O）
```

## 3. 生成链

```text
contracts/*.tsp
  └─ tsp compile ─→ generated/openapi.yaml + generated/schemas/*.json
        ├─ Orval ─→ packages/contracts/src/generated/
        │            types.ts · zod.ts · client.ts（fetch）· hooks.ts（TanStack Query）· msw.ts（模拟）
        └─ datamodel-code-generator ─→ py/packages/hub-contracts/src/hub_contracts/generated/（Pydantic v2）
```

- 一条命令：`mise run gen`。生成物入库，方便 Agent 直接读类型；CI 重新生成一遍，与提交的不一致就失败。
- 生成文件第一行写“由 contracts 生成，勿手改”。
- `mise run contracts:check`：用 oasdiff 把当前 OpenAPI 和 main 分支比较，有破坏性变更就失败（除非 PR 带了对应的 ADR 和版本号升级）。

## 4. 约定

| 项目 | 约定 |
|---|---|
| 字段名 | camelCase |
| 日期 / 时间 | `YYYY-MM-DD` / ISO 8601 带时区 |
| 比例与收益率 | 0–1 小数（`0.0123` = 1.23%），显示时再格式化 |
| 金额 | 元或美元的数值，字段名写明币种（`amountCny`、`valueUsd`） |
| 枚举 | 字符串联合类型 |
| 错误 | `application/problem+json`（RFC 9457），带 `type` `title` `status` `detail` |
| 分页 | 游标分页：`?cursor=&limit=`，返回 `nextCursor` |
| 版本 | 路径前缀 `/v1`；只做增量兼容的改动；破坏性改动需要 ADR + `/v2` 或迁移方案 |
| 幂等 | 计算任务写入用 `PUT` + 自然键（如 `/v1/internal/markets/days/{date}`），重复写入结果相同 |
| 出处 | AI 生成的字段所在对象带 `generatedBy: { capability, version, model, at }` |

## 5. 三类接口

| 类别 | 前缀 | 鉴权 | 调用方 |
|---|---|---|---|
| 公开 | `/v1/public/*` | 无，只读 | 公开站构建、任何人 |
| 私有 | `/v1/*` | 会话（通行密钥登录） | 控制台 |
| 内部 | `/v1/internal/*` | 服务令牌（`Authorization: Bearer`） | 计算任务 |

服务令牌另外可以读私有前缀下的全部 `GET` 接口（计算任务要读自选股、期次、论文等），但不能调用私有前缀下的写接口。

另有：`/auth/*`（Better Auth 自带路由，含通行密钥和 MCP 的 OAuth 端点）、`/mcp`（MCP 服务）、`/.well-known/*`（OAuth 元数据）、`/v1/health`。控制台原样代理这四类路径，不改写前缀（`01` 第 5 节）。

## 6. 契约测试

- API 的每个集成测试都用生成的 Zod 校验响应（Vitest + Cloudflare 的 Workers 测试环境）。
- CI 另跑一次基于契约的随机测试（Schemathesis，对本地 `wrangler dev`）。
- T01 把 `fixtures/` 里的老数据转换成新格式的样例，放在 `fixtures/samples/`（例如 `marketday-2026-08-28.json`、两篇论文的 `Paper`、一期早报的 `Edition`），并用 JSON Schema 校验通过。这是契约写对了的第一个检验，也是后续测试和前端开发的数据。

## 7. 前端的模拟开发

- Orval 生成的 MSW 处理器 + `fixtures/samples/` 里的真实样例，前端在 API 还没实现时就能完整开发和测试。
- 控制台开发模式默认开 MSW；`VITE_USE_MOCKS=0` 切到真实 API。
- 公开站构建支持 `DATA_SOURCE=fixtures`，用样例数据构建，不依赖 API。
