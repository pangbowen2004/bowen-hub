# 07 实施计划与验收

## 1. 怎么推进

- 开发由多个 Agent 并行完成：一个**编排者**按 `tasks/graph.yaml` 分派任务，若干**工作者**各做一个任务，规则见 `11`。
- 全部工作分成 31 个任务、9 个波次（`tasks/README.md`）。同一波次、依赖都已合并的任务可以同时做；最宽的第 3 波有 10 个任务。
- 每个任务的完成标准：`accept` 里的每一项都有真实输出，写在 `docs/progress/<任务ID>.md`；CI 全绿；编排者审查后合并。
- Kevin 只在 5 个关卡介入（第 3 节），平时只和编排者对话。

## 4. 市场对照（M-1）的容差

`hub market compare <日期> [--input <文件>]`：读 `hub market eod --dry-run` 的输出（不给 `--input` 时用 `fixtures/tushare` 的录制数据现场计算）和 `fixtures/market/close-analysis-<日期>.json`（老格式，字段对应关系写在对照代码里），输出一份差异报告。

| 类别 | 字段 | 要求 |
|---|---|---|
| 计数 | 样本数、涨/跌/平家数、20 日新高/新低、涨停/跌停/触板/炸板、最高板、首板/多板、昨日涨停数、晋级数、跌逾 7%、风格四组家数、行业个数（31） | 完全相等 |
| 比例和收益 | `advanceShare` `medianReturn1d` `aboveMa20Share` `sealRate` `advancementRate` `previousLimitPremium` | 差 ≤ 1e-9 |
| 金额 | `turnoverCny`、资金流各项 | 完全相等（按元取整后） |
| 合成分 | 温度、情绪总分 | 相等（1 位小数）；分项差 ≤ 0.01 |
| 技术位 | MA5/10/20、ATR20、支撑、压力 | 差 ≤ 1e-6 |
| 方向（官方） | 16 个方向的 `return1d` `return5d` `return20d` | 差 ≤ 1e-9 |
| 方向（成员） | 宽度、MA20、成交占比等 | 不比较（成分是当前快照，8 月 28 日之后已经变了） |
| 行业 | 每个行业的样本数、`return1d`、阶段 | 预期完全一致；不一致时列出差异最大的 5 个行业并说明原因（通常是行业成员表来源不同），交给 Kevin 判断 |
| ETF | 每组只数、`amountWeightedReturn1d` | 预期一致；`fund_basic` 名单变化会带来少量差异，列出来说明 |

老系统已知与新口径不同、**不算差异**的地方：连板回看天数（10 → 30，8 月 28 日最高 7 板，不受影响）、删除的外部价位、删除的 `relativeVsCsi300`、昨日涨停口径的修正（`03` 第 4.1 节：按交易日历取上一交易日；昨日涨停数、晋级数等出现差异时，报告列出受影响的股票，能被这条修正解释的算通过）。
