## 交付

`hub migrate news-legacy` 与 `hub migrate watchlist` 已实现。`--dry-run` 仅只读源、转换并使用生成 Pydantic 验证，不创建 HTTP 客户端；`--verify` 只读 API 逐期及逐篇核对，不写数据。两标记互斥，错误退出1。默认配置定位仓库 config；`--config` 可传独立配置目录。旧目录只由进程 LEGACY_NEWS_DIR 获取，不读 `.env`，不硬编码旧路径。

旧 JSONL 每行转 legacy-日期期次，只有今日要闻综述与实际 Top5。原摘要、理由、分类/主题与发布时间保留；不补齐五条，不调用模型。规范 URL 作为 Article 自然身份；跨期重复文章最后一份写入搜索，但每期仍嵌入当时的原条目，期次不去重丢失。批写每批40篇，全部写入经过既有 API。重复日期或未知字段明确失败，避免静默覆盖/丢字段。

来源仅按当前配置显示名称（不区分大小写）对照，未知映射 legacy。不猜旧来源别名。旧 mode 无新业务字段、timestamp 无明示时区，记录模式统计及未映射理由；generatedAt、generatedBy、AI用量、邮件信息保持null，不能把旧摘要冒充新运行时生成。文章发布时间解析原始 ISO/RFC 格式并保持明示时区；中文源额外空格和 +0800 已覆盖，不推定无时区日期。

自选股默认 nullable 标的/板块ETF、空 aliases、active=true，生成契约验证30条初值。仅 GET 确认表为空时批写；非空无条件跳过，不覆盖控制台已改资料。verify 比较全部代码及字段，用户改名/停用会明确报告差异并保持原数据。
