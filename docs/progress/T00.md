## 与文档不一致或没做完的

1. **TypeScript 7 与 dependency-cruiser**：typescript 当前稳定版是 7.0.2（原生版，不再提供旧的编程接口），dependency-cruiser 18.4 只支持 TypeScript < 7，装了 7 会**悄悄跳过所有 .ts 文件**。做法：仓库的 tsc 用 7.0.2；在 pnpm-workspace.yaml 的 `packageExtensions` 里只给 dependency-cruiser 配 TypeScript 6.0.3。需要旧编程接口的工具（如 Astro 的 `astro check`）请在自己的包里另装 `typescript@6`。
2. **pnpm 12 的默认值**：依赖包的安装脚本默认不运行，没列入 `allowBuilds` 的会让安装失败。设了 `strictDepBuilds: false`（没列出的只警告），并预先允许 esbuild、msw、sharp、workerd。pnpm 12 对 pnpm-workspace.yaml 里不认识的设置会直接报错。
3. **Biome 共享配置放在根 biome.json**（docs/01 第 7 节写的是放在 packages/config）：Biome 2 的单仓模式就是一个根配置，子目录用 `"extends": "//"` 继承；packages/config 只放 tsconfig 预设。
4. **tsconfig 基础配置放在 packages/config/tsconfig/base.json，根 tsconfig.base.json 指向它**：如果反过来（预设用 `../../../tsconfig.base.json` 继承根文件），经包名引用预设时，Vite/Vitest 按软链接路径解析会找不到根文件。
5. **turbo 的两处设置**：`agentGuidance: false`（否则 turbo 检测到 AI Agent 会往 AGENTS.md 末尾加一段英文，已还原 AGENTS.md 并确认之后不再加）；`cacheDir: ".turbo/cache"`（否则各 worktree 共用主目录的缓存，turbo 自己的文档提醒产物里含绝对路径时会指到别的 checkout）。
6. **import-linter 的边界**：hub-core 的协议固定放在 `hub_core.protocols`，领域包的纯逻辑模块（含各包的 `common`）从 hub-core 只能引用它，也不能引用本领域的编排模块和各 `commands.py`；`commands.py` 归编排层。“不做文件 IO”无法用导入规则检查。纯逻辑模块的规则只查直接导入：它们可以调用 hub-ai，而 hub-ai 调模型本来就要联网，查间接链路会误报。
7. **.astro 文件里的导入**：dependency-cruiser 本身不解析 Astro 组件；tools/arch/src/astro.ts 用 Astro 官方编译器把 .astro 的脚本和模板表达式转成临时 TSX 交给同一套规则检查（含会被浏览器执行的 `<script>`），tools/arch/test/astro.test.ts 覆盖。
8. **额外加了一条工具规则 `workspace-import-resolvable`**：`@bowen-hub/…` 的导入解析不到文件时报错，否则上面几条规则会漏掉它。这要求工作区包的 `exports` 不构建也能解析（直接指向 TS 源码）。
9. **Lighthouse 首屏 JS 预算按页面归类**（docs/05 第 10 节）：首页、单篇、列表（spaces、archive 列表、weekly）、方法、周报、about ≤ 50 KB；观测台 `/directions/`、`/validation/`（含交互表格）≤ 120 KB；其余页面 ≤ 250 KB（包括 2D 图谱）；3D 页不限；KB 按 1024 字节；性能、可访问性 ≥ 90 不含 /graph/ 和 /universe/。LHCI 的静态服务器会 gzip，量到的大小就是文档说的 gzip 大小；tools/tasks/test/lighthouserc.test.ts 用两个站的真实路径核对了归类。
10. **CI 的细节**：ci.yml 只调用 `mise run …`（生成物一致一步按 docs/11 第 8 节另跑 `git diff --exit-code` 和未提交新文件检查）。`check`、`test` 用 `--continue-on-error`，一次看到全部失败项，失败时照样返回非零。“评测”“性能”两步由 `mise run ci:changes` 判断改动范围，推到 main 时不跑（PR 里已经跑过）。uv 由 mise 安装，按 docs/12 第 3 节用 setup-uv 只做缓存。
