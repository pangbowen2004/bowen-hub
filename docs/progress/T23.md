## 实现

- 接通 17 个生成契约处理器：公开 9、私人事件 3、内部写入 5。市场日与摘要同一行原子写入；列表采用日期/ID 稳定游标；指数历史保留最新 250 条并按日期升序返回。私人写入沿用签名 Cookie 与 Origin；内部写入沿用服务令牌。
- Repo、Service 与两个 MCP 工具共用查询路径；Python API 客户端逐页读取全部摘要与假设，不把第一页当完整账本。假设更新在 SQL 条件中保护已经结算的结果。
- 收盘命令按真实交易日历执行采集、核心就绪检查、T21 计算、T22 结算及生成、六指数原始历史、日文档、周报、参考说明和最后的站点派发。非核心缺失仍发布明确的不完整状态，核心缺失在截止前等待、截止后失败；完整既存日默认跳过，失败后需要强制重跑时由操作者使用 --force。
- 回填按真实交易日顺序处理，逐日不派发，只在最后一次发布后派发一次。历史模式不生成起始日期之前的新假设，不把已结算记录改回 PENDING。旧历史账本缺失会明确失败，不拿空账本替代迁移。
- dry-run 输出 day、summary、hypotheses、weekly 本地快照，不写 API、不发邮件、不派发站点、不调用 AI。
- 工作流 market-eod 按 UTC 09:05–14:05 的工作日六轮运行，保留手动日期及 force，主分支检出。仅新闻之外所需市场、内部 API、邮件和派发凭据接线，没有模型凭据。

## 根批准的边界取舍

1. IndexBar 的 preClose、return1d 均为必填真实数字。Repo 等待共享迁移 0003_abandoned_blockbuster.sql 增加 nullable pre_close、return1d；新写入保存原始字段，旧不完整行返回明确错误，不补算或填 0。本任务没有改共享 schema/migration。
2. 空 API 缺前四日摘要时，优先查 API，才用 T20 真实交易日采集及 T21 compute/day_summary 建输入缓存。缓存记录日期、上一交易日、来源、membershipAsOf、版本和实际请求；不发布预热 MarketDay，不借未来数据。Run stats 记录 API 缺失日期及实际补算日期，可用 --warmup-cache 指定独立缓存目录。
3. 历史成员口径沿用现有真实 membershipAsOf 元数据，不能声称今天名单就是历史时点名单。M1 严格比较仍为 184/218，剩余 34 项失败，不以本任务实现覆盖为已匹配。
