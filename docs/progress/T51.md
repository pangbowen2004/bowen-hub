## 交付

- `hub migrate market-ledger`：读 `LEGACY_MARKET_DIR/data/hypotheses/ledger.json`（或 `--source`），按 docs/06 第 2 节转成 `Hypothesis`，`POST /v1/internal/markets/hypotheses/batch`（每批 40 条，按 ID 覆盖；API 对已结算的同 ID 保留原结果）。
  - `--dry-run`：只读、转换、用契约校验、打印统计，不联网；`--verify`：只读 API 逐项核对；两者互斥（退出码 1）。
  - `--verify` 默认还做补跑后的历史核对（docs/06 第 4 节、M-3、M-4）：2026-07-01 至最近一个已收盘交易日每个交易日都有 `MarketDay`（也不该有非交易日的）、周内最后一个交易日都有周报且 Research Error 只含未确认、没有到期日早于最近交易日的 `PENDING`。`--no-history` 只核对账本本身（补跑前用），`--through YYYY-MM-DD` 指定截止日。交易日历用 TuShare `trade_cal`（走本地缓存），需要 `TUSHARE_TOKEN`。
- `hub migrate market-events`：读 `.../data/events/calendar.json`，`POST /v1/internal/markets/events/batch`；同样支持 `--dry-run`、`--verify`、`--source`。
- 映射严格按 docs/06：结果 `DATA_PENDING→PENDING`、`SOURCE_CONFIRMED→CONFIRMED`（说明前加“来源确认：”）；`settlement.actual→actual`；`generation.engineVersion→engineVersion`（没有就不写）；`mode=realtime`；事件 `status` 映射、删 `discovery`。老数据里每个键都有去处：保留的写进契约模型，要删的在统计里列出次数，未登记的键直接失败；规则和实际值经契约校验后必须与老 JSON 完全相同（防止契约默认忽略多余键而静默丢字段）。数量基准 61 条 / 79 条，不符就在写入前停下。
- 失败只打印类别或已审过的短说明，不打印老数据正文、URL、请求头、令牌。
- 代码：`py/packages/hub-market/src/hub_market/migrate/`（`ledger.py` `events.py` `transfer.py` `history.py` `commands.py` `errors.py` `shared.py`）；测试：`py/packages/hub-market/tests/migrate/`（48 项）；共享路径：`py/apps/hub-cli/tests/test_commands.py` 里两个旧占位断言换成帮助与真实行为断言（`--dry-run` 与 `--verify` 互斥）。

## 补跑遇到的三处缺陷（都在别的任务的代码里，我没有改）

线上真实历史数据暴露的，之前的离线测试和 2026-08-24 至 08-28 的录制都碰不到。

**缺陷 1（T21，`compute/directions.py`）**：同花顺“玻璃基板”（886111.TI）官方日线从 2026-06-30 才有，“MLCC”（886112.TI）从 2026-07-30 才有；更早的日期接口返回零行，`DataFrame` 没有任何列，`filter(pl.col("trade_date") <= stamp)` 抛 `ColumnNotFoundError`，整天计算失败。函数下面本来就有 `official.is_empty() → return None`（方向整块为空，`dataStatus.missing=["directions"]`，这正是 docs/03 第 7 节对 `ths_daily` 缺失的约定），只是被前面的 `filter` 抢先崩了。2026-07-01 起的日子，以及它们的前 4 个交易日预热，全会碰到。
- 复现：`cd py && uv run --no-sync python -c` 里用 `recorded(ROOT, date(2026,8,28))` 把某个 `ths_daily/<code>` 换成 `pl.DataFrame()` 再 `compute`；或直接 `hub market eod --date 2026-07-01 --dry-run out.json`（需 `TUSHARE_TOKEN`、`HUB_SERVICE_TOKEN`），退出 1“收盘失败（ColumnNotFoundError）”。

**缺陷 2（T21，同一处）**：板块上市首日 `pct_change` 为空（MLCC 的 2026-07-30），`float(official["pct_change"][-1])` 抛 `TypeError`。另外两个板块在首日后紧接的那个交易日没有行（玻璃基板缺 07-01、MLCC 缺 07-31），这种情况原有的 `trade_date != stamp → return None` 已经能处理。
