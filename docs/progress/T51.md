## 交付

- `hub migrate market-ledger`：读 `LEGACY_MARKET_DIR/data/hypotheses/ledger.json`（或 `--source`），按 docs/06 第 2 节转成 `Hypothesis`，`POST /v1/internal/markets/hypotheses/batch`（每批 40 条，按 ID 覆盖；API 对已结算的同 ID 保留原结果）。
  - `--dry-run`：只读、转换、用契约校验、打印统计，不联网；`--verify`：只读 API 逐项核对；两者互斥（退出码 1）。
  - `--verify` 默认还做补跑后的历史核对（docs/06 第 4 节、M-3、M-4）：2026-07-01 至最近一个已收盘交易日每个交易日都有 `MarketDay`（也不该有非交易日的）、周内最后一个交易日都有周报且 Research Error 只含未确认、没有到期日早于最近交易日的 `PENDING`。`--no-history` 只核对账本本身（补跑前用），`--through YYYY-MM-DD` 指定截止日。交易日历用 TuShare `trade_cal`（走本地缓存），需要 `TUSHARE_TOKEN`。
- `hub migrate market-events`：读 `.../data/events/calendar.json`，`POST /v1/internal/markets/events/batch`；同样支持 `--dry-run`、`--verify`、`--source`。
- 映射严格按 docs/06：结果 `DATA_PENDING→PENDING`、`SOURCE_CONFIRMED→CONFIRMED`（说明前加“来源确认：”）；`settlement.actual→actual`；`generation.engineVersion→engineVersion`（没有就不写）；`mode=realtime`；事件 `status` 映射、删 `discovery`。老数据里每个键都有去处：保留的写进契约模型，要删的在统计里列出次数，未登记的键直接失败；规则和实际值经契约校验后必须与老 JSON 完全相同（防止契约默认忽略多余键而静默丢字段）。数量基准 61 条 / 79 条，不符就在写入前停下。
- 失败只打印类别或已审过的短说明，不打印老数据正文、URL、请求头、令牌。
- `hub market backfill --no-dispatch`（`eod/commands.py`，登记的共享路径）：只写数据，不在末尾派发 `markets-updated`；默认行为不变。

## 补跑遇到的三处缺陷（已按裁定修复）

线上真实历史数据暴露的，之前的离线测试和 2026-08-24 至 08-28 的录制都碰不到。

1. **T21 `compute/directions.py`**：同花顺“玻璃基板”（886111.TI）官方日线从 2026-06-30 起，“MLCC”（886112.TI）从 2026-07-30 起；更早日期接口返回零行，`DataFrame` 没有任何列，`filter(pl.col("trade_date") <= stamp)` 抛 `ColumnNotFoundError`，整天计算失败。复现：`hub market eod --date 2026-07-01 --dry-run out.json`（需 `TUSHARE_TOKEN`、`HUB_SERVICE_TOKEN`），退出 1“收盘失败（ColumnNotFoundError）”。
2. **T21 同一处**：板块上市首日 `pct_change` 为空（玻璃基板 06-30、MLCC 07-30）→ `float(None)` 抛 `TypeError`；两个板块在首日后紧接的下一个交易日还没有行（玻璃基板缺 07-01、MLCC 缺 07-31）。复现：`hub market eod --date 2026-08-05 --dry-run out.json`（预热 07-30 时崩，退出 1“收盘失败（TypeError）”）。
3. **T22 `hypotheses/engine.py::_resolved`**：用 `{**hypothesis.model_dump(), …}` 重建结算副本，把没设置过的可选字段变成显式 null（老账本 DIRECTION_PERSISTENCE 假设的 `rule.baseline.memberCodes`、没有 `generation` 的记录的 `engineVersion`）。`ApiClient.post_batch` 用 `exclude_unset=True` 序列化，请求里多出 `"memberCodes": null`，API 的校验是 `optional`（不是 `nullable`），整批假设写入 HTTP 400，补跑在 08-11 失败；老账本里 `HYP-20260810-TOP-DIRECTION`、`HYP-20260828-TOP-DIRECTION` 必中。复现（本机 `wrangler dev` API，不碰线上）：`services/api/.dev.vars` 写 `APP_MODE=local` 和任意 `HUB_SERVICE_TOKEN`；`mise run db:migrate:local`，`pnpm --filter @bowen-hub/api dev` 起 API；对它跑 `hub migrate market-ledger`；再取 `HYP-20260810-TOP-DIRECTION`，`Hypothesis.model_validate({**row.model_dump(), "result": "NOT_CONFIRMED", "settledOn": "2026-08-11", "actual": {…}, "resultNote": "x"})`，用 `model_dump(mode="json", exclude_unset=True)` POST 到 `/v1/internal/markets/hypotheses/batch`。实测输出：`baseline 里的 null 字段: ['memberCodes'] → HTTP 400 请求参数或正文不符合契约`。
