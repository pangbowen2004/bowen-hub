## 实现

- `editions/commands.py` 注册真实 `hub news morning|premarket|weekly`，保留 `--date/--no-email/--no-ai/--force`，盘前另有 `--ignore-window`。调用 T10 采集、T11 确定性管线、T12 Runtime 能力；未改模型、提示词、评分器或契约。运行失败只暴露安全错误类型，异常正文/凭据不进入输出。
- `collect.py` 使用既有 RSS、Alpaca、SEC、FRED、Finnhub、Tiingo；Alpaca 缺 key 明确失败并降级 RSS。来源一次失败不会被同源后续成功覆盖；未知日程 importance 为 `unspecified`，T11 FOMC 保留 high。股票/ETF 使用 Alpaca `all` 与 Tiingo `adjClose`，同一证券两个端点不混源，不能以不同来源首尾制造涨跌。周报股票窗口复用交易日计算；既有 T11 未定义周度加密币窗口，因此不编造 BTC/XRP 周变化。
- 财报确认复用 T12 原文证据检测：标题本身不确认财报，失败/不明确的 6-K 附件保持候选；没有 EPS 不等同于无财报。RSS 标的别名先按 T11 规范化，再形成财报材料。数值仅来自原材料。
- `repository.py` 仅通过既有 API 写事实/AI 调用/来源健康/Edition/HTML/Run。批量最多 40，正确展开完整时间线 RootModel；历史版次分页并拒绝重复游标。周报目标自然键超过第一页仍查找，历史补跑扩大 API days，再按 T11 窗口筛选。
- `service.py` 顺序为 running Run→交易日/盘前时窗→已发送幂等→采集/AI→阅读预算裁剪→事实、期次和 HTML 归档→SMTP→sentAt→成功 Run。早退不采集/调用 AI；`force` 仅允许重发，不能绕过时窗/交易日。新 `--no-email` 版次 sentAt=null，不推进成功发送历史；强制重建已有版次保留已经发生的真实 sentAt。SMTP 成功但 API 回写失败会记录实际 sent 并提示重跑前核对邮箱，不声称跨 SMTP/API 原子发送。
- 邮件 `render/mail.py` 使用 Jinja2 自动转义和 css-inline 构建内联样式、640px 表格、栏目锚点、红涨绿跌、纯文本版本和来源/AI 费用页脚。仅允许无凭据 http(s) 来源链接。正文计数含可见链接标题，排除 URL 和页脚；超预算删除完整条目，不截断财务数字。删除条目后不保留可能过期的 lede/国际概览，记录降级，不循环调用模型。周报事实点来源与顶层来源合并去重。日程来源失败时显示未能确认安排，不冒充没有日程。
- 复用已有 Mailer 的 SMTP 初次+3次退避，不叠加重试；使用 `email.fromName=美股新闻室`。三个工作流采用既定 cron、手动参数、冻结安装/生成和已合并 main，按任务串行且不取消正在发信的运行。
