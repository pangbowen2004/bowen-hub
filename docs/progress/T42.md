## 已实现

- 既有 GET `/v1/internal/export/{table}`：仅生成契约列出的22张业务表，鉴权表、令牌表、FTS与任意SQL标识符无法导出。使用服务令牌鉴权，私人会话不能代替；保持数据库原始列名、JSON字符串、NULL与数值。固定自然键排序与分页，复合键包含全部分量，数字键按数值排序。默认20/最大100，跨表或错误类型游标明确400。
- `hub export --directory <已检出的数据仓库> [--date YYYY-MM-DD] [--force]`：逐表、逐页写JSON，单表临时文件完成后替换；数据仓库git提交仅包含22个导出文件，不连带其他已暂存文件。必须远端push成功才通过新闻API清理365天前文章；API、分页、commit/push失败保留数据库、不prune。成功日期默认跳过，force显式重跑。所有数据库写入经API，没有直接写其他领域DB。
- 月度费用按实际当前新加坡月份统计，历史业务日期不改预算月份；超过既有monthlyBudgetUsd才发预算提醒。成功SMTP之后才写budget-alert succeeded，同月已有成功提醒则跳过；发送失败不写提醒成功。失败阶段使用固定中文名称，错误正文/URL/凭据不进入通知与CLI输出。
- data-export.yml 每天UTC19:30、evals-weekly.yml 每周六UTC19:00；均支持手动date/force，固定concurrency且不取消正在运行的任务。私有数据仓库checkout不持久化凭据；Python仅从Settings进程环境取得既有自动化令牌，通过push子进程Git环境配置内存注入，不写gitconfig、参数或远端URL。周评测调用公共CLI `hub evals run --weekly --write-api --report weekly-evals.md`；on-change、无正式用例跳过和运行记录/失败通知由根的公共接线实现，不在hub-core反向导入hub-ai。失败报告仍上传artifact。
