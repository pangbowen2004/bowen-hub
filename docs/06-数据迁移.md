# 06 数据迁移

## 0. 规则

- 老项目目录**只读**：迁移命令只能读老**数据**文件（YAML、JSON、Markdown、PDF、CSV）。**不要打开老代码文件**（`*.py`、`*.js`、`*.mjs`、`*.cjs`），需要的规则都已经写在本文档里。
- 迁移是 `hub migrate <对象>` 子命令（代码在各领域包的 `migrate/` 里），**在 Kevin 的 Mac 上运行**（老数据在那里），通过 API 的内部接口写入：`HUB_API_URL` 指向线上 API，带服务令牌。
- 可以重复运行：全部是按自然键覆盖写入（`PUT` / 批量覆盖），跑几次结果都一样。
- 先 `--dry-run`：只读老数据、转换、用契约校验，打印统计，不写 API。确认无误再正式跑。
- 老路径写在 `.env` 的 `LEGACY_*` 变量里（见文末），不要硬编码。
- 迁移完成前，老系统照常运行；新系统验收通过后，再由 Kevin 停掉老的定时任务（第 5 节）。

## 2. A 股观测台

老数据在 `~/Documents/量化/market-observatory/data/`。

**策略：历史快照不做格式转换，而是用新管线重算。** TuShare 的历史数据都能取到，所以直接 `hub market backfill`，所有日期走同一套代码；老快照只用来对照。

步骤：
1. **先对照**：`hub market compare 2026-08-28`，与 `fixtures/market/close-analysis-2026-08-28.json` 比较（容差见 `07` 第 4 节），通过后再继续。
2. **导入老假设账本**（`hub migrate market-ledger`）：`hypotheses/ledger.json`（61 条，2026-08-07 至 2026-08-28）→ `POST /v1/internal/markets/hypotheses/batch`。
   - 字段：`createdOn` / `dueOn` / `title` / `scope` / `confirmation` / `invalidation` / `risk` / `counterEvidence` / `rule` / `result` / `settledOn` / `resultNote` 保留；`settlement.actual` → `actual`；删除 `evidenceIds`、`generation.sourceSnapshotSha256`、`integrity`。
   - 结果映射：`DATA_PENDING` → `PENDING`；`SOURCE_CONFIRMED` → `CONFIRMED`（`resultNote` 前加“来源确认：”）；其余不变。
   - 11 条没有 `rule` 的早期手写假设（2026-08-07、08-10、08-11 生成）原样保留，`rule = null`；其中到期仍是 `PENDING` 的，补跑结算时一律记为 `INCONCLUSIVE`（`03` 第 5.2 节）。
   - 所有导入的记录标 `mode = "realtime"`。
3. **导入事件日历**（`hub migrate market-events`）：`events/calendar.json`（79 条）→ `POST /v1/internal/markets/events/batch`。`status`：`OFFICIAL_CONFIRMED` → `confirmed`，`PENDING_OFFICIAL_CONFIRMATION` → `pending`；其余字段改成 camelCase 后照搬；删除 `discovery` 块。
4. **补跑历史**：`hub market backfill --start 2026-07-01 --end <今天>`（在 Mac 上或手动触发的工作流里跑都可以）。
   - 从 7 月开始，是为了让“近 60 日趋势图”上线时就有数据。
   - 假设只从 `config/market.yaml` 的 `hypotheses.startDate`（2026-08-31）起生成；这之前的假设以老账本为准。补跑生成的假设标 `mode = "backfill"`，上线后定时任务生成的标 `realtime`。
   - 补跑到 2026-08-11 时会结算老账本里 5 条到期未结算的假设（2026-08-10 生成），补跑到 2026-08-31 时结算另外 4 条（2026-08-28 生成）。
   - 周报按新规则全部重新生成（老周报把“证据不足”算进了 Research Error，不迁移）。
5. **事件来源清单**：`events/sources.json`（15 个官方来源）已经整理进 `config/market_event_sources.yaml`，不用再迁。

不迁移：`evidence/`、`metrics/`、`observations/`、`reports/`、`methods/`、`source-documents/`（外部 PDF）、`sources/`（参考图片）、`provider/tushare-close.duckdb`（新系统自己取数）、`runtime/`。

## 3. 论文库（`hub migrate papers`）

老数据在 `~/Documents/ChatGPT/科研/论文阅读/`，每篇论文一个目录 `03-论文档案/<paper_id>/`（89 个）。

对每一篇：读老文件 → 组装 `Paper`、`PaperSummary`、`PaperPrivate` → 用契约校验 → 处理 PDF（抽页文本、生成 `pages.jsonl`、`pages.txt`、页图，和入库流水线用同一段代码）→ 写入：

```text
PUT /v1/internal/papers/{id}/files/source.pdf、pages.jsonl、pages.txt、pages/<n>.png
PUT /v1/internal/papers/{id}            { paper, summary }
PUT /v1/internal/papers/{id}/private    PaperPrivate
```

全部写完后运行 `hub papers derive`。
