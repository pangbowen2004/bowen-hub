# ADR-0015 MCP 的论文问答同样在 Durable Object 中运行

## 背景

ADR-0014 把 `POST /v1/papers/{id}/ask` 交给免费的 SQLite Durable Object 执行，因为解析整篇原文和模型的流式输出在普通免费 Worker 里超出每次请求 10 ms 的 CPU 上限。MCP 的 `papers_ask`（docs/09 第 6 节）调用的是同一段问答代码（`papers.qa`），但 `/mcp` 请求原本在入口 Worker 里直接执行，没有走这条路；按 ADR-0014 的实测，它在线上会同样超限。

## 决定

`/mcp` 先在入口 Worker 里完成来源与令牌核对，只要请求里含 `papers_ask` 的调用（包括批量请求），就把原始请求连同令牌转交一个独立的 Durable Object 执行（每次一个对象，不保存状态，加内部标记头防止再次转交）。对象里运行的仍是同一个 Hono 应用，会用同一份令牌再核对一次；其余工具和握手继续在入口 Worker 里执行。没有绑定该命名空间时（本地最小环境）在原处执行。

## 理由

沿用 ADR-0014 已经验证过的做法，不新增服务、不买付费版、不改模型与提示词；先在入口核对再转交，没有授权的请求不会唤醒对象；转交前只读取不超过 256 KiB 的请求体并解析方法名，成本远低于问答本身。

## 后果

- 每次 `papers_ask` 经 `/mcp` 多一次对象调用和一次令牌核对（一次 D1 读取）；Durable Objects 的免费额度与 ADR-0014 合并观测。
- 线上 CPU 未测：本任务用假模型验证接线，真实问答及对象内 CPU 与 P-11 一并由 T52 在额度恢复后实测。
- docs/01 第 10 节的 ADR 索引需要由编排者补一行。
