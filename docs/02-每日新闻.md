# 02 美股新闻室（每日新闻 v2）

> 老 Daily News 的升级版：以美股为主，保留国际与科技栏目。**新闻和公告为中心，不做行情与财务数据管线**（ADR-0011）。
> 原则是少而精：宁可少一条，也不放一条没用或没出处的。

## 1. 目标与原则

Kevin 做美股短线（持有 1–3 天），需要在三个时间点快速知道“发生了什么、跟我的自选股有什么关系、今晚要盯什么”。

1. **每条都要回答两个问题**：发生了什么？为什么值得看？答不出第二个就不放。
2. **每个事实都有出处**：链接到原文；AI 写出的数字必须能在原文里找到（自动校验，找不到就删掉这个数字）。
3. **自选股优先**：和自选股有关的放前面；没有消息的自选股只用一行带过。
4. **只陈述，不建议**：不写买卖建议、目标价、仓位。
5. **有阅读时长预算**：超预算就删低分内容，而不是缩短每条。
6. **中文输出**，公司名第一次出现写中文名（英文名）或常用名。

## 2. 三个版次

| 版次 | 发送时间（新加坡） | 覆盖窗口 | 阅读预算 | 栏目 |
|---|---|---|---|---|
| **早报** | 每天 07:30 前（07:10 开始生成） | 上一期早报以来（约 24 小时） | ≤ 6 分钟（约 2,500 字） | 导语 · 收盘快照 · 自选股动态 · 美股要闻 · 财报 · 公告与内部人 · 今晚日程 · 国际与科技 |
| **盘前简报** | 美股交易日开盘前 45 分钟（夏令时约 20:45，冬令时约 21:45） | 当天早报以来 | ≤ 3 分钟（约 1,000 字） | 今晚三件事 · 新消息 · 盘前财报 · 今晚日程 |
| **周报** | 周六 09:30 前（09:10 开始生成） | 本周美股交易日 | ≤ 10 分钟（约 4,000 字） | 本周主线 · 本周表现 · 自选股周记 · 财报回顾 · 重要公告 · 下周日程 · 国际大事 |

- 美股交易日和休市日用 `exchange_calendars` 的纽交所日历（XNYS）判断。
- 周日、周一早上（新加坡）没有新的美股交易日：早报的美股部分改成“周末要闻”（周日）和“本周前瞻”（周一：本周宏观日程和自选股财报）。
- 盘前简报只在美股交易日发送；美股休市日跳过。

## 3. 自选股

- 清单在 `config/us_watchlist.yaml`，初始内容是 Kevin 9 月从 moomoo 导出的自选；以后在控制台增删（写进数据库，配置文件只作初始值）。
- 类型：`stock`（有自己的新闻和 SEC 公告）、`etf`（只看相关主题新闻）、`leveraged_etf`（并入标的，比如 TSMX → TSM、AVGX → AVGO）、`crypto`（BTC、XRP，看加密新闻；IBIT 并入 BTC）。
- 公司的 SEC 编号（CIK）运行时从 SEC 的 `company_tickers.json` 自动对照，不手填。
- 标了 `verify: true` 的代码首次运行时确认是否是有效的美股代码，无效就在控制台提示 Kevin。

## 5. 处理流程（三个版次共用）

```text
采集 → 归一 → 关联股票 → 去重聚类 → 规则打分 → AI 加工 → 组版 → 渲染 → 写入 → 发送 → 记录
```

| 步骤 | 做什么 | 确定性？ |
|---|---|---|
| 采集 | 各适配器按覆盖窗口取数据；每个来源记健康状态 | 是 |
| 归一 | 统一成 `Article`：`kind`（news / filing / press_release / macro）、标题、链接、时间（UTC）、摘要、语言、付费墙标记 | 是 |
| 关联股票 | Alpaca 自带代码；RSS 用 `$NVDA` 这类写法、公司名和别名（`config/us_watchlist.yaml` 的 `aliases`）匹配 | 是 |
| 去重聚类 | 规范化链接相同，或标题相似度 ≥ 0.85，或（关联股票相同且时间相差 < 6 小时且标题词重合 ≥ 50%）→ 视为同一事件；保留来源权重最高的一条（权重相同时按 `config/news_sources.yaml` 里的顺序），其余作为“其他报道” | 是 |
| 规则打分 | 来源权重 + 时效 + 关键词 + 涉及自选股 +3 + 涉及大市值公司 +1 + 计量付费墙 −1（权重在 `config/newsroom.yaml`） | 是 |
| AI 加工 | 见第 7 节；每个能力都有降级方案 | 否 |
| 组版 | 按第 6 节的规则生成 `Edition` 文档（符合契约），超出阅读预算就按分数从低到高删 | 是 |
| 渲染 | 邮件 HTML（jinja2 + css-inline）+ 纯文本；控制台网页版直接读 `Edition` | 是 |
| 写入 | 先把数据存进 API，邮件发不出去时控制台也能看到：`POST /v1/internal/news/articles/batch`、`filings/batch`、`insider-trades/batch`、`calendar/batch`、`earnings-cards/batch`；`PUT /v1/internal/news/editions/{id}` 和 `/html`；每个来源的健康状态 `PUT /v1/internal/news/sources/{id}/health` | 是 |
| 发送 | SMTP（沿用老 Daily News 的邮件配置），失败重试 3 次；成功后回写期次的 `email.sentAt` | 是 |
| 记录 | 开始和结束各一次 `PUT /v1/internal/runs/{runId}`；AI 用量 `POST /v1/internal/ai-calls/batch` | 是 |

- 版次 ID：`{kind}-{新加坡日期}`，如 `morning-2026-09-30`。同一版次重跑会覆盖；已经发送过的默认不重发，`--force` 才重发。
- 命令：`hub news morning|premarket|weekly [--date] [--no-email] [--no-ai] [--force]`，以及 `hub news sources --check`。

## 6. 各版的版面规则

### 6.1 早报

1. **导语**（能力 `news.edition_lede`）：3 句话——隔夜美股整体怎样、最大的一件事、和自选股的关系。只用本期已经整理好的事实。
2. **收盘快照**（可选）：一行指数 ETF（SPY、QQQ、DIA、IWM、SMH）的涨跌幅；10 年期美债、VIX（有就显示）；自选股涨跌幅条（按涨跌排序，红涨绿跌）。只显示，不做分析。
3. **自选股动态**
   - 入选（满足任一）：窗口内有相关新闻；有 SEC 公告；有财报；日涨跌幅绝对值 ≥ 3%（阈值在 `config/newsroom.yaml`）。
   - 排序：有财报的 → 涨跌幅绝对值大的 → 新闻多的。
   - 每只（能力 `news.ticker_digest`）：`代码 名称 涨跌幅` + 发生了什么（≤ 80 字）+ 为什么重要（≤ 60 字，可空）+ 1–3 个来源链接。
   - 归因规则：只有来源支持时才写原因；没有直接消息时写“未找到直接相关消息”；流水线会先算出“是否与板块同向”（对照该股在自选股清单里的 `sectorEtf`，没有就用 QQQ：两者同向，且 ETF 涨跌幅绝对值 ≥ 2%，阈值 `thresholds.sectorSyncMove`）作为事实交给 AI，AI 只能据此写“与板块/大盘同步”。
   - 没入选的自选股合成一行：“无重要消息：AAPL、WMT、……”。
4. **美股要闻**：先去掉已在自选股动态里出现的事件（按聚类），再把规则分前 20 条交给能力 `news.us_rank`，选 6–8 条，主题要分散（宏观与美联储、财报、AI 与半导体、大型科技、加密、政策与地缘、其他），每条 2–3 句中文摘要 + 为什么重要 + 来源。
5. **财报**：昨晚盘后和今早盘前发布财报的自选股、以及 `config/newsroom.yaml` 里的大市值公司。每家一张卡片（能力 `news.earnings_card`）：营收（同比）、每股收益（注明 GAAP 或调整后）、最多 3 个关键业务指标、指引（有就写）、一句话要点。数据来自 SEC 8-K（Item 2.02）附件 EX-99.1 新闻稿原文；找不到时用财报新闻。**每个数字都必须在原文里出现**，否则删掉。免费数据没有一致预期，所以不做“超预期/不及预期”判断；新闻稿或新闻里自己写了的可以引用并注明出处。
6. **公告与内部人**（自选股）：
   - 8-K：按 Item 分类显示（2.02 财报、5.02 高管变动、1.01 重大协议、8.01 其他事件等），重要的用能力 `news.filing_digest` 写 1–2 句要点。
   - 10-Q / 10-K：只提示“已发布”并给链接。
   - Form 4（解析 XML，不用 AI）：买入（交易代码 P）全部列出；卖出（S）只列金额 ≥ 100 万美元的；行权、代扣税（M、F 等）不列。格式：`姓名（职位）买入/卖出 N 股，均价 $X，合计 $Y`。
   - 增发（S-1、S-3、424B*）、大股东变动（SC 13D / 13G）：列出并附链接。
7. **今晚日程**（时间一律显示新加坡时间，自动处理夏令时）：
   - 宏观：FRED 发布日历里、`config/newsroom.yaml` 重点清单上的数据（CPI、就业报告、PPI、零售销售、GDP、个人收入与支出/PCE、JOLTS、初请失业金等），发布时间按配置里的美东时间换算；FOMC 会议日（配置里的日期，每年初更新一次）。
   - 财报：自选股和大市值公司，标“盘前 / 盘后”。
   - 没有安排就写“今晚没有重要日程”。
8. **国际与科技**：沿用老 Daily News 的做法（附录 A），压缩为 Top 5 + 最多 10 条简短摘要（每条 2–3 句）。
9. **页脚**：各来源状态（失败的写原因）、本期 AI 用量与费用、控制台网页版链接。

### 6.2 盘前简报

1. **今晚三件事**（能力 `news.edition_lede`，盘前模式）：三行，每行一句。
2. **早报之后的新消息**：先自选股（规则同 6.1 第 3 条，但入选条件不看涨跌幅），再市场层面（最多 5 条）。
3. **盘前已发布的财报**：卡片同 6.1 第 5 条。
4. **今晚日程**：宏观数据（精确到分钟）、盘后将发布财报的名单。
- 不做盘前价格：免费行情只有 IEX 一家交易所的成交，盘前代表性差。

### 6.3 周报

1. **本周主线**（能力 `news.edition_lede`，周报模式）：250–350 字。
2. **本周表现**（可选）：指数 ETF 周涨跌；自选股周涨跌表。
3. **自选股周记**：本周有事的每只自选股 1–3 条要点（能力 `news.ticker_digest`，周模式，输入是本周的新闻、公告和财报卡片）。
4. **财报回顾**：本周所有财报卡片。
5. **重要公告与内部人**：本周汇总。
6. **下周日程**：宏观、FOMC、自选股与大市值公司财报。
7. **国际大事一周**：本周国际与科技栏目里得分最高的 5 件事。

## 7. 本产品用到的 AI 能力

能力的格式、档位、自治等级和评测方法见 `10`。清单在 `capabilities/`，提示词在 `prompts/`。

| 能力 | 输入 | 输出 | 档位 | 降级 |
|---|---|---|---|---|
| `news.edition_lede` | 本期已组好的事实（要闻、自选股、财报、日程） | 导语 / 今晚三件事 / 本周主线 | frontier | 不放导语 |
| `news.ticker_digest` | 一只自选股的涨跌幅、是否与板块同向、相关新闻与公告 | 发生了什么、为什么重要、引用的来源 | balanced | 列出新闻标题和链接 |
| `news.us_rank` | 规则分前 20 的美股新闻 | 选出 6–8 条，中文摘要与理由 | balanced | 按规则分取前 6 条，只放标题 |
| `news.earnings_card` | 财报新闻稿原文 | 关键数字（带原文片段）、指引、要点 | balanced | 只放“已发布财报”和链接 |
| `news.filing_digest` | 8-K 正文 | 1–2 句要点 | fast | 只放 Item 分类和链接 |
| `news.classify` `news.curate` `news.brief` | 国际与科技栏目（沿用老 Daily News） | 见附录 A | fast / balanced | 见附录 A |

**持续变好的闭环**：控制台每一期都可以打 1–5 分，并可对单条内容点“没用”或“有错”。这些反馈存进数据库，定期整理进 `evals/` 的评测集；换模型、改提示词时用它们检验是否真的变好（见 `10`）。

## 8. 邮件与控制台

- 邮件：单列 640px；不用 flex / grid；顶部目录的标签点击可跳到对应栏目（锚点）；红涨绿跌；每条都有“原文 →”链接；标题 `📰 美股早报｜2026-09-30`、`⏰ 盘前简报｜…`、`🗓 美股周报｜…`；发件人显示名 `Bowen Newsroom`。
- 控制台（`05`）：各期归档（网页版与邮件同内容）；个股页（一只股票的新闻、公告、财报卡片时间线）；全文搜索（D1 FTS5）；每期打分与反馈；自选股增删；来源健康状态。

## 10. 失败与降级

| 情况 | 处理 |
|---|---|
| 某个来源失败 | 其余照常；页脚写明“X 暂不可用（原因）” |
| Alpaca 新闻不可用 | 自选股新闻退回到 RSS 关联匹配 |
| 某个 AI 能力失败 | 用第 7 节表里的降级方案，页脚注明 |
| 全部 AI 失败 | 发送“标题清单版”：每个栏目只列标题、来源、链接 |
| 发信失败 | 重试 3 次；仍失败则任务以非零码退出，GitHub Actions 标红并发失败通知（通知也失败就只记日志） |

## 11. 验收

| 编号 | 检查 |
|---|---|
| N-1 | 三个版次都能用 `fixtures/http/news/` 的回放数据生成；确定性部分（采集、聚类、打分、组版）用快照测试锁定 |

| N-5 | 周报周六送达，含下周日程 |
| N-6 | 去掉 Alpaca key 运行：自选股新闻退到 RSS 匹配，版面照发并注明 |
| N-7 | 用错误的模型 key 运行：发出“标题清单版”，页脚注明 |
| N-8 | `news.*` 能力的评测全部达到阈值（`10`） |
| N-9 | 上线后连续 5 个美股交易日，早报和盘前简报都准时送达，其间的周报周六送达；Kevin 在控制台的平均打分 ≥ 4 |

## 附录 A：国际与科技栏目（沿用老 Daily News）

- 源清单：`config/news_sources.yaml` 里 `section: international` 的源（BBC、NPR、SCMP、TechCrunch、The Verge、Hacker News、Ars Technica、MIT Technology Review、Hugging Face、VentureBeat、36氪、IT之家、TechNode 等）。
- 规则（全部沿用，配置在 `config/news_keywords.yaml`）：只取最近 36 小时；链接规范化 + 标题相似度 ≥ 0.85 去重；分类基础分 + 关键词加分（英文按词边界匹配）；计量付费墙 −1；每个分类最多 5 条。
