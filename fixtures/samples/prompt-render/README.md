# 提示词渲染的共享测试向量

T04 的两个渲染器（Python `hub-ai`、TypeScript `packages/ai`）都读这里的向量：用 `template.md` 和 `input.json` 渲染，结果必须与 `expected.json` **逐字相等**。规则来自 `docs/10` 第 5.1 节（序列化细节是开工前预检 Q09 的结论）。

这个目录不是契约模型的样例，样例校验测试会跳过它。

## 格式

每个子目录是一个向量：

| 文件 | 内容 |
|---|---|
| `template.md` | 提示词模板，格式与 `prompts/*.md` 相同：一级标题、给人看的说明、`## system`、`## user`、`<!-- -->` 注释 |
| `input.json` | 能力的输入：顶层字段就是占位符 `{{ 字段名 }}` 里的字段名 |
| `expected.json` | `{ "system": "…", "user": "…" }`：两节渲染后的精确文本 |

## 覆盖的规则

| 规则（`docs/10` 第 5.1 节） | 向量 |
|---|---|
| 只取 `## system` 和 `## user` 两节（一级标题、引用块、其他二级标题都不要；`###` 小标题属于正文；行中间的 `## system` 字样不是标题） | 01，07，08 |
| 去掉 `<!-- -->` 注释（行内、跨行、节首节尾） | 02 |
| `{{ 字段名 }}` 替换；同一占位符出现多次、system 里的占位符也替换 | 03，06 |
| 字符串原样放入（换行、引号、反斜杠、`$&` `$1` `$$`、值里的 `{{ name }}` 字样都原样保留） | 03 |
| 对象和数组序列化成 JSON：两空格缩进、保持输入的键顺序、中文不转义；嵌套的 `null`、`[]`、`{}` 按 JSON 原样写 | 04，07，08 |
| 值为 `null`、空字符串、空数组时写成“（无）” | 05 |
| 布尔值写成 `true` / `false`；顶层空对象和缺失字段写成“（无）”，嵌套空对象仍按 JSON 原样写（2026-10-01 编排裁定） | 09 |
| 整数原样写（`0` 不是空值，负数带负号） | 06 |
| 真实提示词：`prompts/news_brief.md`、`prompts/news_us_rank.md` 的副本 | 07，08 |

## 向量里采用、但文档没有逐字写明的处理

这些是写出期望值时必须定下的细节，取的都是最直接的读法；T04 照此实现。编排者如有别的决定，改向量即可。

1. **节的范围**：`## system`、`## user` 必须是行首的二级标题；节的内容从标题的下一行开始，到下一个行首的 `## ` 二级标题（或文件末尾）为止。
2. **节内容去掉首尾空白**（空行、空格）。
3. **注释直接删掉**：从 `<!--` 到最近的 `-->`（可以跨行）连同两端标记一起删除，前后文字原样相接。
4. **替换只做一遍**：放进去的值不再当作模板处理，值里的 `{{ name }}` 字样原样保留；TS 里替换时用函数，不要用会解释 `$&` 的替换字符串。
5. **JSON 序列化**：Python 用 `json.dumps(value, ensure_ascii=False, indent=2)`，TS 用 `JSON.stringify(value, null, 2)`；对这些向量两者逐字相同。

## 文档没写、所以向量里没有的情况

遇到时先问编排者，不要自己定：

- 图片字段（如 `papers.review` 的 `pageImages`）在占位处“只写页码”的具体写法；
- 浮点数（Python 的 `1.0` 与 JS 的 `1` 写法不同）；
- 注释单独占一行、又在节的中间时，删掉后那一行是留成空行还是整行去掉；
- 不规范的占位符（`{{x}}`、`{{  x  }}`）；
- 注释里出现 `## user` 这样的标题时，先去注释还是先分节；
- 对象里像整数的键（如 `"1"`）：JS 会把它们排到其他键前面，和 Python 的键顺序不同；
- Windows 换行 `\r\n`。
